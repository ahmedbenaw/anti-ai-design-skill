## Findings on what distinguishes AI-generated UI

### F1. Cross-tool structural convergence: different AI tools produce near-identical layouts for the same prompt
- **Claim:** Generative UI tools converge on similar structural/layout solutions; structure is more homogeneous than color.
- **Evidence/metric:** Design Homogeneity Index (DHI) over visual, color, and layout similarity across 120 interfaces from 5 tools x 24 tasks; "color choices showed greater variation than structural organization."
- **Papers:** #1.
- **Strength:** measured.
- **Measurable check:** Compare a candidate page's layout skeleton (DOM region tree, section ordering: nav / hero / 3-feature-cards / testimonial / CTA / footer) against a reference corpus of AI-tool outputs; high structural similarity to the AI-cluster centroid with low distance variance is a flag. Layout can be extracted from HTML (landmark/section sequence) or from screenshots (block segmentation).

### F2. AI outputs cluster tightly in embedding space; human designs spread wider
- **Claim:** Populations of AI-generated designs occupy a smaller region of visual/semantic embedding space than populations of human designs.
- **Evidence/metric:** CLIP-embedding pairwise distances: Midjourney chair designs cluster more densely than Red Dot award winners (Mann-Whitney U significant) (#10); LLM creativity-test responses across vendors more mutually similar than human responses, controlling for response structure (#9); inter-model homogeneity exceeds intra-model repetition on 26K open-ended prompts (#8).
- **Papers:** #8, #9, #10 (design-adjacent domains, not web UI specifically).
- **Strength:** measured (in adjacent domains); observed for web UI specifically.
- **Measurable check:** Embed screenshots (CLIP) of the candidate design plus N regenerations of the same brief; compute mean pairwise distance and distance-to-nearest-neighbor vs a human-website baseline distribution (e.g. sampled from Design2Code's 484 real pages). Low dispersion → AI-typical.

### F3. Rationale-implementation gap: AI UIs claim design decisions they don't ship
- **Claim:** Generative UI tools verbalize design rationales (accessibility, error recovery, states) that are absent from the generated artifact.
- **Evidence/metric:** Thinking Fidelity Score: >25% of user-facing rationales unimplemented on average, 34% for functional requirements; Principle Adherence Score mean 0.54; 4/5 tools implement ≤6% of functional principles.
- **Papers:** #1.
- **Strength:** measured.
- **Measurable check:** Static-check HTML/CSS for the presence of interaction states (`:hover`/`:focus-visible`/`:disabled` rules, error/empty/loading states, `aria-*` beyond boilerplate, form validation handlers). Uniform absence of functional depth beneath polished surface styling is an AI-typical signature.

### F4. Missing functional interactivity, system status, and error recovery
- **Claim:** AI-generated UIs systematically lack visibility of system status, user control/error recovery, state management, and real accessibility, while looking complete at surface level.
- **Evidence/metric:** Design Theater tier-3 (functional) tasks show the worst adherence; failures "remain invisible during surface-level review."
- **Papers:** #1; consistent with #3 (models fail at element recall and layout correctness) and #5 (VLMs cannot iterate toward correct designs without human questioning).
- **Strength:** measured.
- **Measurable check:** Count distinct interactive states per component; count dead links/`href="#"`; check whether buttons have handlers; ratio of decorative to functional elements.

### F5. LLM-generated code carries robust stylometric fingerprints — including in web languages
- **Claim:** AI-written code (incl. JavaScript) is machine-detectable and even attributable to the generating model from structural/dataflow patterns, not surface tokens.
- **Evidence/metric:** CodeT5-JSA: 95.8%/94.6%/88.5% attribution accuracy over 5/10/20 LLMs on 50K Node.js programs, robust to comment stripping and identifier mangling (#13); cross-language transformer detector 84.1% ± 3.8% over 10 languages (#14).
- **Papers:** #13, #14; direction supported by broader code-stylometry work surfaced in search (2506.17323, 2409.01382, 2603.04212).
- **Strength:** measured (for JS/general code; HTML/CSS-specific detectors not found).
- **Measurable check:** Train or reuse a code-stylometry classifier on HTML/CSS/JS; cheap heuristics meanwhile: comment style and density, consistent semantic-but-generic class naming, uniform formatting, boilerplate section comments ("/* Hero Section */"), utility-class (Tailwind) dominance, identical CDN/setup preambles.

### F6. Training-data monoculture seeds a recognizable default stack
- **Claim:** The synthetic corpora used to train screenshot-to-code models are themselves homogeneous — WebSight's 2M pages are all LLM-written Tailwind CSS with Unsplash imagery — so models trained/tuned on them reproduce that specific look.
- **Evidence/metric:** Dataset construction description: Mistral-7B concepts → DeepSeek-Coder-33B HTML, "Tailwind CSS" chosen for all pages, Unsplash keyword images (#4).
- **Papers:** #4; #2 (identifies Tailwind/Bootstrap defaults and template reuse as a homogenization vector across the vibe-coding lifecycle).
- **Strength:** measured for dataset composition; observed/speculative for the downstream causal claim.
- **Measurable check:** Detect Tailwind utility classes (or compiled Tailwind palettes: exact hex values of the default Tailwind color scale, default spacing scale multiples of 0.25rem), `source.unsplash.com`/placeholder image URLs, default `rounded-xl shadow-lg` combinations.

### F7. Named surface traits of the "vibe-coded" look
- **Claim:** LLM-generated sites share minimalist whitespace, standard sans-serif typography, predictable hero images, and generic framework-default patterns.
- **Evidence/metric:** Illustrative example and grey-literature synthesis only (Figure 1 of #2); the paper explicitly does not measure these traits.
- **Papers:** #2.
- **Strength:** observed/speculative (the paper itself flags the lack of empirical evidence).
- **Measurable check:** Distributional stats over a candidate corpus: font-family entropy (share of Inter/system sans stacks), hero-section presence and geometry, whitespace ratio, palette entropy, gradient usage. These are proposed here as operationalizations — the literature has not yet validated thresholds.

### F8. Generated pages simplify: element recall and layout fidelity are the weak axes
- **Claim:** When reproducing real designs, MLLMs drop visual elements and simplify/regularize layouts rather than producing wrong-but-complex ones.
- **Evidence/metric:** Design2Code fine-grained metrics (block-level element matching, text/position/color match + CLIP visual similarity, human-validated): "models mostly lag in recalling visual elements... and generating correct layout designs" (#3); Sketch2Code models cannot steadily improve fidelity across turns (#5).
- **Papers:** #3, #5.
- **Strength:** measured.
- **Measurable check:** Element-count and layout-depth statistics: AI pages tend toward lower DOM depth variance, fewer distinct component types, more regular grids. Compare element inventory richness against human pages of the same genre.

### F9. AI-in-the-loop homogenizes human designers' output too
- **Claim:** Even human-authored designs made with AI assistance converge: users fixate on AI examples and different users produce less distinct results.
- **Evidence/metric:** Between-subjects experiment, 60 participants: higher fixation, fewer/less varied/less original ideas with AI image generator (#11); 36-participant study: lower cross-user semantic distinctness with ChatGPT (#12).
- **Papers:** #11, #12; supported by #9.
- **Strength:** measured.
- **Measurable check:** Not directly checkable on a single artifact; corpus-level check: cross-site similarity within a portfolio/agency's recent output rising over time indicates AI-assisted convergence.

### F10. AI-generated imagery inside UIs is machine-detectable via forensic artifacts
- **Claim:** Hero images/illustrations generated by diffusion models carry spectral and spatial artifacts (abnormal frequency distributions, upsampling checkerboards, non-camera noise patterns, texture inconsistencies) detectable at 92–99% within-distribution.
- **Evidence/metric:** Survey of spatial, frequency (DFT/DWT/DCT), fingerprint, patch-based, and CLIP-based detectors; UnivFD-benchmark accuracies 92–94% cross-generator (#16).
- **Papers:** #16; human-limits complement in #15.
- **Strength:** measured (for photographic imagery; flat vector-style UI illustration is under-studied).
- **Measurable check:** Run frequency-domain / CLIP-based AI-image detectors on extracted `<img>` assets and hero backgrounds; also check for Unsplash/placeholder URLs vs local bespoke assets (ties to F6).

### F11. Automated judges under-discriminate — evaluation itself is a tell-limited instrument
- **Claim:** MLLM judges compress variance and cannot separate visually similar UIs or judge usability, so "an MLLM said it looks human/good" is weak evidence.
- **Evidence/metric:** ±1 accuracy >75% but ~50% (random) pairwise accuracy on ease-of-use and on similar UI pairs; reduced score variance vs humans (#17).
- **Papers:** #17.
- **Strength:** measured.
- **Measurable check:** Use MLLM judgment only as one ensemble member; prefer objective distributional checks (F1, F2, F6, F8) over judge scores.

### F12. Intra-model repetition: regenerate-and-compare exposes AI provenance
- **Claim:** A single model re-prompted on the same brief returns strikingly similar outputs, so similarity between a suspect artifact and fresh regenerations is evidence of AI origin.
- **Evidence/metric:** Intra-model repetition and inter-model homogeneity on Infinity-Chat, 25 human annotations per example (#8).
- **Papers:** #8; #1 (same effect across tools for UI specifically).
- **Strength:** measured (text domain); measured across tools for UI (#1).
- **Measurable check:** "Regeneration test": prompt several current models with the inferred brief of the suspect page; compute structural (F1) and embedding (F2) similarity of results to the suspect. High similarity to the AI cluster → likely generated.

## Measurable metrics proposed in the literature

- **Design Homogeneity Index (DHI)** — visual/color/layout similarity across tools' outputs for the same task (#1).
- **Thinking Fidelity Score (TFS)** — fraction of stated design rationales actually implemented (#1).
- **Principle Adherence Score (PAS)** — fraction of embedded UX principles recognized/implemented (#1).
- **Design2Code automatic suite** — high-level CLIP visual similarity + low-level block/text/position/color element matching, validated against human judgment (#3).
- **CLIP-embedding pairwise-distance clustering** (density of a design population) + Mann-Whitney U on distance distributions (#10).
- **Novelty proportion P_novelty = U/(U+S)** (unique vs shared design vocabulary against a human corpus) (#10).
- **Cross-user/inter-model semantic distinctness** via embedding similarity of outputs to the same prompt (#8, #9, #12).
- **TrueSkill-derived pairwise expert ranking with calibrated confidence intervals** for design quality (#7).
- **Code-stylometry classifiers** on AST/dataflow structure (CodeT5-based; robust to renaming) (#13, #14).
- **Spectral/frequency-domain artifact analysis, patch inconsistency, model fingerprints** for embedded imagery (#16).
- **MLLM-judge correlation metrics** (Pearson/Spearman/Kendall, MAE, ±1 accuracy) — usable but with known blind spots (#17).
- **55%-improved LLM critique via UICrit few-shot prompting** — a recipe for automated design-flaw detection (#6).

## Counter-evidence / limits

- **Humans are near chance on AI imagery:** 53.76% accuracy vs MidJourney v7 portraits; per-image accuracy ranged 26–87%, and gains require 15+ seconds of deliberate inspection (#15). Visual "tells" checklists are unreliable at scrolling speed.
- **Detector generalization is fragile:** image detectors lose accuracy across generator families (GAN-trained fail on diffusion), object categories, and scene distributions (#16). A detector tuned on today's tool outputs may fail on next quarter's.
- **The flagship homogenization paper for web design is non-empirical:** #2 provides a harm taxonomy and lifecycle, cites text-domain homogenization studies (Agarwal 2025; Anderson 2024), and explicitly calls for empirical evidence — no measured distribution of colors/fonts/layouts in vibe-coded sites exists there.
- **Quality is converging on parity:** LLM-generated UIs matched expert designs in roughly half of the tested cases and were overwhelmingly preferred over plain markdown (#18); UI-Bench treats tool ranking, not human-vs-AI discrimination (#7). "Looks worse than human work" is not a dependable tell.
- **MLLM judges are near-random on similar UIs and on usability** (#17) — automated "does this look AI?" judgments inherit these blind spots.
- **Homogeneity evidence is mostly from adjacent domains:** #8, #9, #11, #12 measure text/ideation/product-design, not web UI. Only #1 (120 interfaces) measures UI homogenization directly, and #10's embedding-clustering method used chairs, not screens.
- **Stylometry detectors target JS/general code:** no published detector specifically for HTML/CSS authorship was found (#13, #14 are the nearest evidence).

## Gaps

1. **No published classifier for "AI-generated UI screenshot" or "AI-generated HTML/CSS" as such.** Code stylometry (#13, #14) and image forensics (#16) are the nearest neighbors; the direct task appears unstudied — a buildable opportunity (WebSight + tool outputs as positives, Design2Code/Common Crawl as negatives).
2. **No measured distributional statistics of AI web-design outputs** (font-stack frequencies, palette entropy, hero-layout prevalence, Tailwind-default incidence) across models/tools; the traits everyone names (#2) remain unquantified beyond DHI's 120 interfaces (#1).
3. **No paired human-vs-AI website dataset for detection research** (matched briefs, matched genres) — Design2Code (human) and UI-Bench/Design Theater/WebSight (AI) could be combined but were not built for this.
4. **Temporal drift unstudied:** whether the AI-design distribution shifts with each model generation (and detectors decay accordingly) has no UI-domain measurement, though image forensics documents the analogous problem (#16).
5. **Flat/vector UI illustration forensics:** AI-image detection literature focuses on photographs; the gradient-blob illustration style common in AI-generated landing pages is untested territory (#15, #16).
6. **Causal loop untested:** whether synthetic-corpus training (WebSight, #4) measurably causes downstream homogenization in tool outputs is asserted (#2) but never experimentally isolated.
